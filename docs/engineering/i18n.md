---
title: Internationalization
description: How CashLift wires next-intl today and how to extend it.
---

CashLift ships English-only product copy today. `next-intl` is configured in `src/services/i18n/request.ts` and loaded through `NextIntlClientProvider` in the workspace shell.

## Canonical pattern

1. Add stable keys to `src/services/i18n/messages/en.json`.
2. Read messages from server code with `getTranslations`, or import the JSON module in static configuration such as `src/modules/page-shell/navigation.ts` when the label is not rendered inside a hook.
3. Prefer `useTranslations` in client components when the string is rendered in that subtree.

Do not add user-visible copy only in components when the string is part of a reusable navigation or form contract. Keep keys in the message catalog so a second locale can be added without hunting literals.

## Reference

- Message catalog: `src/services/i18n/messages/en.json`
- Wired labels: `WorkspaceNav.overview`, `WorkspaceNav.spendApprovals` in `src/modules/page-shell/navigation.ts`
