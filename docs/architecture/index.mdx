## Source ownership

<FileTree>

- **src/**
  - **app/**
    - Route groups, layouts, metadata, API handlers, auth gates, and route composition.
    - **(marketing)/** — public product, legal, and demo-entry pages.
    - **(public-demo)/** — static read-only workspace tour.
    - **(workspace)/** — Clerk-protected dashboard pages.
    - **api/** — server-only HTTP boundaries for workspace operations.
  - **modules/**
    - Product capabilities, schemas, repository contracts, and feature-specific UI.
    - **workspace/**, **dashboard/**, **spend-requests/**, **invoices/**, **vendors/**, **budgets/**, **cash-actions/**, and **subscriptions/**.
  - **ui/**
    - Generic reusable UI primitives, controlled fields, stories, and styling utilities.
  - **services/**
    - Clerk, Supabase, Sentry, React Query, environment configuration, i18n, and platform integrations.
  - **utilities/**
    - Domain-agnostic helpers.
  - **test/**
    - Shared test setup and feature fixtures.
- **supabase/**
  - Schema and row-level security policies.
- **e2e/**
  - Playwright journeys for demo and production behavior.
- **.storybook/**
  - Storybook configuration.
- **docs/**
  - Blume documentation source.
- **public/**
  - Static product, marketing, and brand assets.
- **scripts/**
  - Repository automation and security checks.
- **.github/workflows/**
  - CI checks and scheduled repository automation.

</FileTree>

Business modules should not casually import other business modules. Routes compose them, while explicit composition modules such as `dashboard`, `workspace`, and `page-shell` own their documented cross-module relationships.

The machine-readable review map lives in
`docs/contributing/architecture/primitives.yaml`. Visual PR recaps use its
stable primitive IDs, connections, code ownership, and invariants to classify
the system impact of a diff.

## Data boundary

Workspace pages resolve data on the server. In demo mode, the resolver returns the typed Studio Nova fixture. In production, it requires Clerk and Supabase configuration, authenticates the user, and uses company-scoped row-level security. Browser code does not query finance tables directly.

## Route groups

- `(marketing)` contains public marketing, use-case, legal, and demo-entry routes.
- `(public-demo)` contains the public read-only workspace tour.
- `(workspace)` contains authenticated dashboard routes for overview, approvals, budgets, cash, invoices, vendors, team, and settings.
- `(auth)` contains sign-in and sign-up routes.

- Run `pnpm build-storybook` to produce the static site.
