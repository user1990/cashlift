# Issue Tracker

CashLift engineering issues are tracked in Linear.

## Workspace configuration

- **Team:** CashLift
- **Team ID:** `6d316b40-0472-4902-bd21-0084784bce34`
- **Issue identifiers:** `TES-*`
- **Access:** use the connected Linear app tools; read the target team and issue before mutating it

## Creating issues

Create issues in the CashLift team in dependency order so later issue descriptions can reference real blocker identifiers. Apply the `ready-for-agent` label when a ticket is fully specified and can be implemented without additional human context.

When the available Linear tools expose native blocking relationships, use them. Otherwise, include a `Blocked by` section with issue references in the description. Do not close or modify a parent issue while publishing child tickets.

## Reading issues

Fetch the complete issue and its comments before deriving a spec, ticket set, or implementation plan. Preserve CashLift domain vocabulary from `CONTEXT.md` in issue titles and descriptions.
