Lesson 07 · Product economics

The expensive part is still the years after the demo

Anyone can scaffold a thin CRM. A maintained product is a team that keeps fixing, securing, and evolving it. Build when the wedge is yours; buy when the burden is the product.

Build vs buyOne retrieval checkNo SaaS obituaries

Win for this lesson

You can decide build vs buy with a named maintenance owner, not with the fact that an agent can generate a first version.

Do not clash

This is not architecture-as-code (lesson 06). You are not encoding dependency direction. You are deciding whether a generated clone is a product or a liability.

Predictions that “CRUD SaaS dies in the agent era” confuse generation cost with ownership cost. If a hosted product still grows while people argue it should vanish, the market is paying for maintenance, trust, and integration—not for the first form.

Build when

  • The workflow is specific to you and will not be maintained by a vendor.
  • You will own bugs, security, and the next six months of change.
  • The 5% you need is truly 5%, and you can ignore the rest forever.

Buy when

  • The vendor’s roadmap includes work you do not want to staff.
  • Failure is a security, compliance, or support problem, not a weekend inconvenience.
  • Your clone would trail a dedicated team within a quarter.

Closing rule for the course: compete at the bottleneck. If you compete with the generator at typing, you lose. If you can locate constraints, ship through them, and keep humans on judgment, software work remains. For proof of a change, return to Teach. For a risky system edit, return to Direct the system.

Retrieval check

What must exist before you replace a paid tool with a generated clone?

Make it yours

Pick one tool you use (notes, CRM, dictation, billing). Write build vs buy with: owner, failure mode, and what you will not rebuild. If you would still build, schedule the first maintenance hour now.
