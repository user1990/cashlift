Lesson 03 · Pipeline

The pipeline is capped by the slowest step

Speeding code generation without speeding the constraint only piles unfinished work. Draw the path from idea to users, then circle what actually limits output.

Theory of constraintsOne retrieval checkOne map

Win for this lesson

You can map one feature as ideate → design/align → build → verify → ship → users, and identify the current bottleneck without proposing more typing.

Do not clash

Do not re-teach architecture fitness functions (lesson 06) or the quality gauntlet. If the constraint is verification, open the gauntlet. This lesson only locates the constraint.

Eliyahu Goldratt’s theory of constraints is a factory idea that maps cleanly onto software: a system’s throughput is the throughput of its bottleneck. Making a non-bottleneck faster creates inventory, not delivery.

A software pipeline

01IdeateWhat is worth building?
02Design / alignShape, owners, other teams
03BuildGenerate and edit code
04VerifyTests, review, “almost right”
05ShipRelease, flags, ops
06UsersFeedback, sales, support

Agents currently compress step 03 in many shops. In a mature product, senior time was already in 02, 04, and 05. In a solo project, the pile-up is often 06. Same model, different circled box.

“Almost right” is not a small remainder

Generated code that is 90% correct still needs a human to find the 10%. That search can cost more than writing the slice. Point at prompt vs check and practical guardrails when you need systems of verification. Do not become the only reader of every line if you can encode checks.

Keep the one-pager nearby: pipeline constraint map.

Retrieval check

You make code generation twice as fast and nothing else changes. What happens first?

Make it yours

Pick one in-flight feature. Draw the six steps. Circle the slowest. Write one action that speeds that circle—not the generator.

Use the bottleneck rule. You do not need the novel’s plot. Throughput is not local efficiency.
