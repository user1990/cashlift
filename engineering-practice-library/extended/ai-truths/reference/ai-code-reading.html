AI Code Reading Reference

When AI writes code, your senior skill shifts from typing every line to reading, tracing, reviewing, testing, and directing the codebase shape.

Short Summary

AI can generate code quickly, but developers still need fundamentals to judge whether the code belongs, works, fails safely, and fits the system. The highest-leverage skill is reading generated code through control flow, data flow, error flow, state, side effects, modularity, and architecture.

Key Points

  • Do not memorize every library method; understand what code does, why it belongs there, and what data it transforms.
  • Trace three flows first: control flow, data flow, and error flow.
  • Check scope, inputs, outputs, state ownership, and side effects before trusting generated code.
  • Review abstraction, modularity, and architecture because AI often solves locally while damaging long-term shape.
  • For web apps, verify the request/response cycle, HTTP semantics, and concurrency behavior under messy timing.

Remember

  • Clean-looking code can still have the wrong path through it.
  • Happy-path generation is not production readiness.
  • Agentic coding means directing placement, tradeoffs, tests, and failure behavior.

Use In Practice

  1. For every AI-generated feature, draw the user action to API to database to UI data path.
  2. Ask where it can fail, who sees the failure, and what evidence logs or tests prove the behavior.
  3. Before merging, ask whether the logic is in the right layer or whether AI created duplicate, leaky, or unnecessary abstractions.

12-Part Review Checklist

ConceptStaff-level questionCommon AI failure
Control flowWhat runs first, what returns early, and what path is skipped?Validation, cleanup, or auth runs after a return or in the wrong branch.
Data flowWhere does data enter, change shape, persist, and render?DTO, API response, cache, and UI type disagree.
Error flowWhat happens when a request, value, permission, or write fails?Only the perfect happy path works.
ScopeWho can read or mutate this value?State or variables leak across boundaries.
Input/outputWhat does this unit require and guarantee?Function signatures lie or return inconsistent shapes.
StateWhere does changing data live, and who owns updates?Duplicated state drifts across UI, cache, server, and database.
AbstractionDoes this hide real complexity or hide important behavior?AI creates helpers that make debugging harder.
ModularityDoes each file have one job and a clear dependency direction?Business logic lands in UI components or route handlers.
ArchitectureDoes this fit the system map?The feature works but violates the repo's established pattern.
Side effectsIs this pure calculation or does it change the world?Writes, emails, cache invalidation, or analytics are mixed into logic.
Request/responseAre method, status, auth, validation, and response shape correct?API semantics are plausible but wrong.
ConcurrencyWhat breaks when two users, jobs, tabs, or retries happen together?Race conditions, duplicate writes, stale UI, or stuck queues.
