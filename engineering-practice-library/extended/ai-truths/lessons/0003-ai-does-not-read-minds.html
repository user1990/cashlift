Lesson 3 of 40

AI does not read minds

Staff-level point: The model needs role, objective, boundaries, inputs, and acceptance criteria. Treat prompts like executable specs.

Real Product / Engineering Example

Turn “review this task” into “act as staff engineer; inspect this task for missing acceptance criteria, migration risk, test plan, and rollback plan.”

Practice Drill

Rewrite one vague automation request into a task brief with role, inputs, constraints, output schema, and done criteria.

Operating Checklist

  • Define the business or engineering outcome before touching tools.
  • Name the owner, inputs, output, verification, and failure path.
  • Use examples or fixtures when quality matters.
  • Make the model show uncertainty or route to a human when needed.
  • Record the reusable prompt, context pack, or runbook.

Feedback Loop

Pass condition: No hidden expectations remain; another engineer could run the prompt.
