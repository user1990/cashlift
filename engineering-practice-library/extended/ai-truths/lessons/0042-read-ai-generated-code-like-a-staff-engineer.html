Advanced Extension 42

Read AI-generated code like a staff engineer

Staff-level point: AI lowers typing cost, so the scarce skill becomes code comprehension, placement judgment, failure analysis, and verification design.

Extracted Summary

The transcript argues that AI-era developers must still understand programming fundamentals, but the emphasis shifts toward reading and directing generated code. The practical checklist is to inspect control flow, data flow, error flow, scope, input/output, state, abstraction, modularity, architecture, side effects, request/response behavior, and concurrency.

Advanced Example: AI-built lead export

An agent adds a CSV export for dashboard leads. It touches UI filters, an API route, a query builder, analytics, and a download helper. The feature may work locally while still exporting the wrong date range, leaking unauthorized rows, timing out on large accounts, or bypassing audit logging.

Your Review Job

Do not review alphabetically. Review by dependency: data contract, query/auth, API response, UI state, export side effect, tests, logs, and rollback behavior.

The 5-Pass Review Workflow

  1. Map the slice. Write one sentence for the feature path: "User clicks X, client sends Y, server validates Z, database reads W, UI receives V."
  2. Trace three flows. Mark control flow, data flow, and error flow before commenting on style.
  3. Separate pure logic from side effects. Keep formatting, filtering, parsing, and validation easy to test; isolate database writes, emails, cache invalidation, file downloads, and analytics.
  4. Check placement. Decide whether logic belongs in component, hook, route, service, model/query layer, background job, or shared utility.
  5. Demand evidence. Require tests or manual verification for boundary cases: empty data, invalid input, auth failure, retry, concurrent action, and large data.

Review Prompt Template

Review this AI-generated diff like a staff engineer.

First, summarize the intended feature in one sentence.
Then inspect in this order:
1. Control flow: early returns, skipped validation, cleanup paths.
2. Data flow: source, transformations, persistence, response, UI rendering.
3. Error flow: bad input, auth failure, network failure, DB failure, empty state.
4. State and side effects: duplicated state, stale cache, writes, emails, downloads, logs.
5. Modularity and architecture: wrong layer, duplicate helper, unnecessary abstraction.
6. Concurrency: duplicate clicks, retries, simultaneous users, background jobs.

Return only:
- blocking bugs
- risky assumptions
- missing tests
- one suggested smaller diff if the implementation is overbuilt

Hands-On Drill

Take one recent AI-generated change. Fill this out before trusting it:

Control flowWhat branch returns early? What must run before return?
Data flowWhat exact object shape crosses each boundary?
Error flowWhat does user see? What does developer see?
StateWhere is truth stored? What is derived?
Side effectsWhat external thing changes?
ArchitectureWhich layer owns this logic?
ConcurrencyWhat happens on retry, double click, or parallel job?
