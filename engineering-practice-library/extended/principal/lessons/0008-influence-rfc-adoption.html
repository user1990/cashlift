Lesson 0008

Influence: RFC and adoption plan

Influence without formal authority comes from clear problem framing, a small pilot, visible results, and an adoption path.

Sprint index

RFC shape

An RFC should be a decision document, not an opinion essay: context, problem, goals, non-goals, options, recommendation, risks, migration, adoption, and metrics.

Primary sources: Architecture Decision Records, Vercel Web Analytics.

Example

Three teams handle API errors differently. RFC proposal: shared Result/Error model, reusable ErrorState, logging standard, and the rule that raw backend messages never go directly to users.

Practice

Write a 5-line RFC skeleton for data fetching and error states.

Write first, then check.

Good answer direction

"I would not try to own every decision. I would make important decisions easier, visible, and repeatable. Start with a pilot, capture evidence, then roll the standard into templates and new features."
