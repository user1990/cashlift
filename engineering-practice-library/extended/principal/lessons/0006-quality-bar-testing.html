Lesson 0006

Quality bar: testing and review boundaries

A useful quality bar prevents recurring mistakes without becoming a bureaucratic wall.

Sprint index

Test by responsibility

Unit tests protect domain rules. Integration tests protect user-visible component behavior. End-to-end tests protect critical business flows. Do not use expensive e2e tests as a replacement for cheaper focused tests.

Primary sources: Testing Library Guiding Principles, Playwright Docs.

Example

Checkout flow: unit test price calculation, integration test promo code and validation messages, e2e test the happy path from report selection to payment confirmation.

Practice

Good answer direction

"E2E should cover critical user flows, integration tests should verify behavior, and domain rules should stay cheap to test in isolation. The quality bar should be fast enough that teams actually use it."
