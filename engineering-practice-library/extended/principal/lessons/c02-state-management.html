C02

State management: predictable architecture

State management starts with ownership boundaries, not with choosing a library.

Sprint index

The rule

Classify state before moving it: server state, domain state, UI state, interaction state, or URL state.

Example

A vehicle report filter belongs in the URL if it should be shareable, near the component if it is temporary UI, and in server/query cache if it controls remote data freshness.

Practice

Pick one feature you know and list five pieces of state. For each one, write owner, lifetime, persistence, and invalidation rule.

Write a concrete answer, then check.

Good answer direction

Strong answer: I choose state placement by ownership and lifetime first. Libraries help after the boundaries are clear.
