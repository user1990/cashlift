Lesson 0005

Performance: budgets and user journeys

Performance is not final polish. It is a product requirement with budgets, regression checks, and real-user metrics.

Sprint index

Start from the journey

For a paid vehicle report, the first trustworthy summary matters more than loading every chart immediately. Optimize the first confidence signal, then defer detail.

Primary sources: web.dev Learn Performance, Core Web Vitals.

LCP

Can the main trust signal appear fast?

INP

Do critical interactions respond quickly?

CLS

Does the page jump while trust is forming?

Bundle

Are deep details blocking the first useful view?

Practice

Write a three-line performance audit: bottleneck, user impact, measurement plan.

Write first, then check.

Good answer direction

"If the report page bundle blocks the first trustworthy summary, I would prioritize summary HTML, lazy-load charts, split route bundles, and add a budget so the regression cannot silently return."
