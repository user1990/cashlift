Microfrontends: independent deployment tradeoffs

Microfrontends buy deployment autonomy at the cost of runtime integration complexity.

Sprint index

The rule

Use them for organizational independence, not just code splitting.

Example

Checkout and report teams may deploy independently, but shared auth, routing, analytics, design tokens, and error handling still need contracts.

Practice

Write one microfrontend boundary and list runtime contracts, shared dependencies, failure mode, and rollback plan.

Write a concrete answer, then check.

Good answer direction

Strong answer: I would choose microfrontends only when team autonomy justifies the operational and user-experience cost.
