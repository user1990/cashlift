Lesson 0003

React / TypeScript: state boundaries

A lot of frontend complexity comes from mixing server state, domain state, UI state, and short-lived interaction state.

Sprint index

Server state

Data owned by the backend: cache, freshness, loading, error, retry, auth, and invalidation rules.

Domain state

Business meaning prepared for UI: confidence, missing data, conflict status, permissions, and derived facts.

UI state

Visible presentation choices: selected tab, open section, sort order, filter text, active panel.

Interaction state

Ephemeral input: hover, drag, optimistic pending state, temporary form edits before commit.

Example

A mileage timeline should not make every component interpret raw API records. Map raw responses into MileageEvent[] with status: "confirmed" | "conflicting" | "missing", then let components render clear states.

Primary sources: React: You Might Not Need an Effect, TypeScript Narrowing.

Practice

Classify each item by owner: server, domain, ui, or interaction.

Good answer direction

"I model API responses separately from UI models. Unstable backend contracts should not leak into components. Components should render a clear domain model, not reinterpret raw data in every section."
