Keyboard-First Accessibility

A quick review sheet for code review and interview answers.

Default rule

Prefer native HTML controls. Native controls bring semantics, keyboard behavior, focus behavior, and platform compatibility before you write JavaScript.

ARIA rule

ARIA can add missing semantics, but it does not add the expected behavior. If you create a custom control, you own keyboard interaction and state updates.

Review checklist

  1. Can every clickable action be reached with Tab or an expected arrow-key pattern?
  2. Is focus visible and easy to find?
  3. Does focus move predictably after opening, closing, deleting, or navigating?
  4. Is DOM order aligned with visual and screen-reader reading order?
  5. Can native HTML replace a custom ARIA widget?
  6. Does text meet at least 4.5:1 contrast for normal body text?
