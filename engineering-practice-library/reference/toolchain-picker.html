Selection rules

  1. Start with the defect. Name what current checks miss before adding a tool.
  2. Prefer repository conventions. Extend an existing runner before introducing a parallel ecosystem.
  3. Prove failure. Intentionally violate the rule and see the command fail.
  4. Keep the fast loop fast. Target changed files or packages; schedule broad mutation if necessary.
  5. Make output actionable. An agent should see the reason and likely repair, not merely a number.
  6. Ratchet baselines. Block new regressions before demanding a global clean slate.

Tools are examples, not endorsements

Availability, operators, counting rules, and maintenance status change. Read the linked official documentation and evaluate fit, licensing, runtime, and false-positive rate before adoption.
