Prompting field guide · lesson 02

Repair the prompt, not just the output.

A good prompt is an operating contract. Today’s win is learning to spot the missing guardrail and add the smallest line that makes the work falsifiable.

Retrieval check

An agent has made two visual tweaks and both missed. What comes next?

Repair pattern

For any weak request, ask four questions:

  1. What is the failure mode?
  2. Which guardrail is missing?
  3. What single prompt line adds it?
  4. What evidence would prove it worked?

Three quick repairs

Preview confusionProve which checkout the browser shows

Weak: Show me the latest version in the browser.

Missing: state identity.

Repair: Prove target checkout → server cwd/command → browser URL/route before using the preview as evidence.

Self-review loopAdd an independent reviewer

Weak: Implement it and verify everything.

Missing: independent review.

Repair: Have a separate reviewer challenge regressions, accessibility, and state conflicts; reconcile its report before completion.

Late permissionStop before remote side effects

Weak: Create the PR when you finish.

Missing: external-action boundary.

Repair: Local edits are allowed; PR creation is not. Stop and show destination, payload, scope, and rollback before asking.

Practice

Take one prompt you use regularly and add: one state line, one preservation line, one independent-proof line, and one authority boundary.
