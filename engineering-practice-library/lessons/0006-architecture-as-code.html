Lesson 06 · Structure

Architecture can fail the build

A diagram explains intent once. An executable dependency rule protects that intent on every change.

Information hidingDependency directionFitness functions

Win for this lesson

You can express one architectural invariant as a machine-checkable allowed or forbidden dependency.

Begin with a reason to change

Parnas’s decomposition criterion is not “one folder per noun.” A module should hide a design decision likely to change. In a refund capability:

COREDomainEligibility and refund decisions.
PORTApplicationCoordinates policy and effects.
EDGEAdaptersPayments, database, email.
UIInterfaceHuman interaction and display.

The core rule should not change because Stripe changes its SDK or because a button moves. Therefore dependencies point inward toward policy, while adapters implement interfaces defined at the boundary.

Human-readable architecture policy

Allowed:
  ui          -> application
  application -> domain
  adapters    -> application

Forbidden:
  domain      -> ui
  domain      -> adapters
  application -> concrete payment SDK

Example dependency-cruiser rule for JavaScript/TypeScript

{
  "name": "domain-does-not-depend-on-edges",
  "severity": "error",
  "from": { "path": "^src/domain" },
  "to": { "path": "^src/(ui|adapters)" }
}

The error is useful only if it teaches the repair: move policy inward, inject a port, or relocate code whose ownership was misidentified.

A good fitness function

  • Protects a consequential invariant, not a cosmetic preference.
  • Names the architectural reason in its error message.
  • Fails locally and in CI with deterministic output.
  • Has a narrow exception process with owner and rationale.
  • Is intentionally violated once to prove the gate actually works.

Do not automate architecture discovery prematurely

Tools can visualize current dependencies, but they cannot decide which business decisions deserve protection. A human should choose the domain language, boundaries, and allowed direction. The machine then prevents drift.

Write one rule

Choose two modules in a real project. Complete: “A must not depend on B because…” Then name the build-time evidence that would detect a violation.

Retrieval check

The domain layer imports a UI toast helper to report an error. What is the strongest structural response?
