# Course Map

This course turns the supplied audit and Spotify-like design brief into a practical prompting discipline. Each lesson should produce one usable artifact or decision.

1. [State before change](lessons/0001-state-before-change.html) — establish the real checkout, runtime, route, and baseline before editing.
2. Diagnose before prescribe — separate symptom, expected behavior, reproduction, hypotheses, evidence, mechanism, and implementation.
3. Delegation contracts — delegate bounded, independently verifiable work with explicit ownership and return schemas.
4. Verification contracts — combine synthetic checks, independent behavior, and final diff review.
5. Visual iteration contracts — after two misses, stop micro-tuning and rewrite invariants, motion, focus, scroll, and reduced-motion behavior.
6. Durable handoffs and project baselines — preserve decisions, rejected alternatives, risks, and the minimum agent contract.
7. External-action gates — separate local edits from commits, pushes, reviews, deployment, publishing, and communication.
8. Spotify-like design prompting — use the full supplied palette, typography, geometry, layout, responsive, and do/don’t system in implementation prompts.
9. [Practical guardrails](lessons/0002-practical-guardrails.html) — repair every recurring anti-pattern, preserve every strength, and turn every rule into a prompt line plus observable proof.
10. [Practical examples](reference/04-practical-examples.html) — apply every anti-pattern and strength to concrete UI, preview, verification, delegation, worktree, and handoff situations.
